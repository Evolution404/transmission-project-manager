## P1.2：系统自维护账号密码认证

最终业务决定（2026-09-12）：业务用户登录不依赖 Cloudflare Access、邮箱验证码或企业 IdP。系统自己维护账号、认证凭据、会话、角色和业务范围；邮箱不进入账号模型。Cloudflare 只承担 Workers、D1、R2、域名/WAF 等基础设施能力。

实现基线：

- 登录标识为大小写不敏感唯一 `username`。管理员创建账号时配置账号、姓名、初始密码、角色、启停和 `all/framework/project` 授权范围。
- 明文密码只存在于浏览器输入内存中。浏览器 Web Worker 使用 Argon2id 派生 32 字节凭据，当前参数为 `m=19456 KiB`、`t=2`、`p=1`、Argon2 v1.3；重计算不占 Worker CPU。
- 服务端不执行 PBKDF2/Argon2。服务端只计算 `HMAC-SHA256(AUTH_CREDENTIAL_PEPPER, derivedCredential)` 并保存 verifier；数据库同时保存每账号随机 salt 和 KDF 参数版本，既不保存明文密码，也不保存浏览器派生凭据。
- `/api/auth/kdf` 对已知和未知账号都返回同形态公开参数；未知账号使用确定性假 salt，登录失败统一返回“账号或密码错误”，避免直接枚举账号。
- 密码最少 15 个字符、最多 128 个字符；允许空格和 Unicode，不设置无意义的字符组合规则。管理员设置的初始密码和重置密码均要求用户首次/下次登录强制修改。
- 连续 5 次失败登录会临时锁定账号；成功登录清零失败计数。安全事件写审计。
- 登录成功签发 256 bit 随机会话令牌，D1 只保存 SHA-256 token hash；Cookie 为 HttpOnly、SameSite=Strict，生产为 Secure，默认绝对有效期 7 天。
- 退出、改密、管理员重置密码和账号停用会撤销相关会话；旧 Cookie 下一次请求立即失效。
- 首次登录且 `must_change_password=true` 时只允许 `/api/me`、修改密码和退出，不能进入业务接口。
- 首管理员只允许一次性 bootstrap：系统成员表为空且 `X-Bootstrap-Token` 与运行时 `BOOTSTRAP_TOKEN` 匹配时才能创建。普通请求永远不能“第一个登录自动当管理员”。
- 后端继续强制角色和范围权限；最后一个启用管理员不能被停用或降权。该约束已经进入数据库条件更新，覆盖并发降权竞态。
- 生产运行时不读取 `Cf-Access-Jwt-Assertion`、`X-Dev-User-*` 等身份头；这些头在 production 测试中被明确验证为无效。

开发期 schema 决策：系统尚未投入正式使用、没有需要保留的真实生产数据，因此按用户明确要求直接重整 `0001` 为当前正确结构，删除旧 `0002` 和本地账号 seed，不建立兼容层。当前迁移锁只约束这份开发基线；正式部署/共享数据出现后恢复只追加迁移规则。

## P3：储备转换（先重点验收）

责任范围：项目/分配/估算/分类表、归并及确认接口、四步转换向导、储备列表与详情。

交付：年度/类别/电压/线路建议分组；人工拆并；标准物资汇总与来源明细双视图；部分分配与剩余需求；物资/施工/其他费用；缺价标记；估算版本；需求类别到储备大类映射与共同费用分摊。

验收：100单位拆为60和40；重复提交及两人并发分配不超过100；相同型号不同单位不合并；未知价格与明确零价区分；类别重复标签不增加金额；混合项目分类金额和已知费用合计相等；单据/明细可反查源表行。

## P4：框架、协议及资金

责任范围：框架/协议/预算/流水迁移与API、费用页面、口径切换、金额与日期共享逻辑。

交付：框架年度目标；协议版本与有效期；子项目预算草稿/确认及多协议分配；独立预算发生/实际费用流水；更正冲销；原子记账与幂等；90%、80%和预算超框架事件。

验收：无协议不能确认发生；跨框架拒绝；一协议多子项目、一子项目多协议的金额不重复；预算不自动产生发生额；90%/80%精确边界；预算合计=框架不超额，超1分预警；预警不擅自硬阻断；0分母显示未配置；并发更新不漏记；旧版本不重复计入。

## P5：出库、实施、结算与反馈

责任范围：出库/实施/结算及范围关联、状态投影、相应界面和附件元数据/私有存取。

交付：项目出库快照和分批范围、实施完成量与实际物资使用、历史记录补录和待关联、结算覆盖及最终标记、四状态和部分进度、结算待办。储备与子项目沿用同一ID。

验收：四种组合均可表达；分批完成60/100不等于整条已实施；剩余未安排需求仍影响总状态；先结算后实施可用；撤销结算后重新待办；历史实施不造出库且关联后不重复统计；附件跨项目拒绝；已有出库不能被修改储备静默覆盖。

## P6：分析、提醒及备份
