# 当前业务基线

版本：2026-09-13。

本文件只记录已经确认、后续实现不能擅自回退的业务事实。具体表结构与 API 见 `DATA_MODEL.md`，界面与交互见 `DESIGN.md`，阶段状态见 `IMPLEMENTATION_PLAN.md`。

## 1. 最终业务主线

系统主线为：

```text
基础台账
  电压等级 1:N 线路 1:N 杆塔
          ↓
抽象需求（可带 0..N 条需求物资）
          ↓
项目储备（需求来源关系 + 独立项目物资）
          ↓
一次项目级出库
          ↓
1..N 个执行任务
          ↓
任务物资供应 / 现场实施 / 任务结算三线并行
          ↓
实施/结算事实回投原始需求四状态
```

框架、执行协议、预算、预算发生、实际费用和结算属于独立资金事实，与上述执行主线关联但不能互相替代。

## 2. 基础台账：电压等级、线路、杆塔

- 严格关系：`VoltageLevel 1:N TransmissionLine 1:N TransmissionTower`。
- 电压等级由管理员统一配置，至少预置：35kV、110kV、220kV、500kV、1000kV、±500kV、±800kV、±1100kV。
- 所有正式业务电压字段来自统一字典/对象选择，禁止自由文本成为正式事实。
- 线路必须属于一个电压等级；同一电压等级下线路名称唯一。线路可停用；被业务引用后不能改变所属电压等级。
- 杆塔号 `tower_no` 是字符串，允许 `#20`、`#20+1`、`G1` 等；`sort_index` 独立表示线路真实顺序。同线路的杆塔号和顺序分别唯一。
- 杆塔可单个新增或批量维护。线路已有需求引用后，为保护历史区段语义，该线路所有杆塔的换线、改号、顺序调整和删除都受保护；仍允许停用。
- 未被业务引用的对象可以删除；被需求/项目引用后只能停用。停用不影响历史显示，新业务不可选择。

正式需求保存：`voltage_level_id`、`line_id`、`location_type`、`start_tower_id`、`end_tower_id`。

`location_type` 只有三种：

- `whole_line`：整条线路，起止杆塔均为空；
- `tower`：单基杆塔，起止杆塔相同；
- `tower_range`：连续区段，起止为两个不同杆塔，并按 `sort_index` 严格正向。

手工需求按“电压等级 → 线路 → 位置类型 → 杆塔”级联选择。Excel 可以填写可读文字，但发布前必须解析到已有台账；未知或停用对象阻止发布，系统不得自动创建线路或杆塔。

## 3. 需求：抽象业务事项，物资不是成立前提

- 需求表达一个需要解决的隐患、工作事项或业务任务，本体不依赖物资。
- 一个需求可以有 0..N 条需求物资子明细；物资允许为空、不完整、后补和变化。
- 需求阶段物资只是“当时已知信息”，不能成为项目最终物资的数量上限。
- 手工新增和标准模板批量导入是等价入口；有批量入口的业务对象必须同时保留手工入口。
- Excel 中同一抽象需求可以占多行，每一物理来源行都必须保留追溯；发布后规范化为一个需求加多条物资子明细。
- 导入中未知电压等级、线路、杆塔属于阻断错误；未知标准物资可以按既定规则作为待映射信息处理，但不能伪造成零价或已核实。

## 4. 项目储备：需求来源与项目物资分开

- 储备项目可在物资尚未明确时创建，允许 0 条项目物资。
- `project_demand_links` 只表达“项目由哪些需求形成”，不继承需求物资数量，也不承担项目物资计划职责。
- `project_material_requirements` 是项目自己的当前物资事实，可以后补、增加、减少、换型。
- 每次项目物资调整必须有修订原因和前后快照。
- 项目物资已经分配到执行任务后，不得删除、换型或缩减到任务累计占用量以下。
- 储备确认形成不可变版本；后续修改形成新修订和新储备版本，不能覆盖历史快照。

## 5. 项目级出库和执行任务

- 项目出库是储备项目正式进入执行阶段的一次项目级状态转换，不是仓库发货。
- 一个项目只做一次项目级出库，并冻结当时的需求来源、项目物资和版本快照。
- 最终主模型不再使用逐物资 `release_lines` 表达项目级出库。
- 只有项目级出库后才能创建正式执行任务。
- 一个项目可以建立多个执行任务；任务是现场执行事实的基本颗粒度。
- 每个任务明确需求范围、现场范围、负责人、计划量和任务物资。

## 6. 任务物资供应、实施、结算三线并行

任务内部三条线互相独立推进：

### 物资供应

- 供应状态属于具体任务物资，不属于标准物资字典。
- 至少保持 `到货数量 <= 发货数量 <= 上报数量 <= 任务物资需求量`。
- 供应使用独立版本控制，并发同版本写入只能一个成功。
- 发生过的供应事实不能被后续项目物资修订静默删除。

### 现场实施

- 实施按任务需求范围记录事实，允许部分实施。
- 60/100 只能表示部分完成，不能直接标记为“已实施”。
- 实施可以登记实际物资使用，但不能把实际使用反推成项目物资计划。

### 任务结算

- 结算按任务需求范围记录覆盖量、金额、最终标记和协议分摊。
- 结算可以先于实施发生。
- 最终结算必须覆盖任务完整需求范围。
- 首次实施后形成结算提醒；最终结算完成后关闭，撤销后重新打开。

供应、实施、结算分别使用自己的版本，不得用一个项目阶段字段替代三条事实线。

## 7. 四状态回投需求

需求的最终反馈状态由实施和结算两个独立维度计算：

| 实施完成 | 结算完成 | 状态 |
|---|---|---|
| 是 | 是 | 已实施已结算 |
| 是 | 否 | 已实施未结算 |
| 否 | 是 | 未实施已结算 |
| 否 | 否 | 未实施未结算 |

系统汇总一个需求在所有任务中的计划范围、实施量和结算覆盖量后判断完成情况。部分完成必须保留进度，不得用四状态掩盖数量事实。

## 8. 框架、协议、预算和费用

- 每个框架有整体额度；一个框架可有多个执行协议。
- 一个项目只属于一个框架；一个协议可以服务多个项目，一个项目可以使用多个同框架有效协议。
- 项目预算、预算确认占用、预算发生、实际费用、任务结算、协议预支是不同事实，必须分别保存。
- 编制预算草稿不要求协议已经有效；确认预算或发生资金流水时必须使用同框架且业务日期有效的协议。
- 预算确认不能自动生成预算发生；结算也不能自动生成实际费用。
- 金额以整数分保存，不使用浮点累计。
- 缺价格是未知，不等于零价。
- 协议使用率达到 90%、框架预算发生达到 80%、预算总额超框架等属于预警，不擅自变成硬阻断。

## 9. 分析、提醒和备份

- 月度/季度分析使用明确口径和规则版本，历史报告保留当时的快照和规则。
- 储备类别分析只统计尚未发生项目级出库项目的当前项目物资金额；已出库项目整体退出当前储备金额分析。
- 施工费/其他费不强行摊入项目物资储备类别；未知价格单独展示。
- 年度事项保留 `month/day/unknown` 日期精度，不补造不存在的具体日期。
- 预警、通知 outbox 和重试必须幂等；关闭浏览器不影响服务端定时任务。
- D1→`ObjectStorePort` 备份是按表分片的逻辑备份，不是跨表一致快照；正式迁移/恢复前需要可靠停写并在独立 D1 中实际恢复对账。当前 production provider 为 Notion，R2/Filesystem 保留为替代后端。
- `auth_sessions` 不随业务备份恢复。

## 10. 认证与权限

- 业务账号由系统自己维护 `username + password`，不依赖 Cloudflare Access、邮箱验证码或企业 IdP。
- 浏览器 Web Worker 执行 Argon2id；服务端只保存带运行时 pepper 的 HMAC verifier，不执行慢 KDF。
- 会话为高熵随机 token；数据库只存 token hash；默认 7 天 HttpOnly 会话。
- 停用、改密、管理员重置密码会使旧会话失效。
- 管理员维护成员、角色和业务范围；最后一个启用管理员不能被停用或降权。
- 前端隐藏控件不能替代服务端权限校验。

## 11. 工程与验收边界

- 所有高风险修改和缺陷修复测试先行。
- 写操作保持幂等键、版本守卫、原子审计和失败回滚。
- 当前开发期旧业务数据允许清理，不需要为旧自由文本业务模型建立兼容主路径；系统账号、权限和审计数据不能误删。
- 已应用迁移冻结，只能新增 migration；当前冻结到 `0012_master_data_write_guards.sql`。
- 本地/合成门禁通过不等于正式上线；真实业务数据、Cloudflare CPU/配额、目标地区网络、通知投递、正式恢复和运维移交仍按 P7 验收。
