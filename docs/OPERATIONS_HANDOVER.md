# 运维移交检查表

版本：2026-09-12。P1.2 已同步系统自维护账号认证；生产 Cloudflare/GitHub 权限与 CI/CD 实际演练在 P7 完成。

## 1. 身份分工

| 身份 | 应承担的职责 | 不应依赖的凭据 |
|---|---|---|
| 资产所有者 / 兜底负责人 | 保留账户所有权、重大授权、紧急恢复 | 日常业务和发布不得要求其登录 |
| 应用管理员 | 在系统内新增/停用成员、角色、框架/项目范围、规则配置 | 不需要 Cloudflare 账号 |
| 技术运维负责人 | 域名、Workers、D1/R2、Secrets、WAF、迁移、故障 | 不共享资产所有者密码或 Global API Key |
| CI/CD 服务身份 | 自动测试、受控发布、迁移 | 使用 account-owned API token，不绑定个人长期 Token |

## 2. 应用内交接

- [ ] 至少有 2 名启用管理员，避免单人失联；后端已禁止停用或降权最后一个启用管理员。
- [ ] 成员账号、角色、授权范围和启停状态与实际职责一致。
- [ ] 新成员通过“管理员创建 username + 初始密码 → 首次登录强制改密”流程，不开放匿名注册。
- [ ] 离岗成员先停用，保留历史审计和业务引用，不普通硬删除。
- [ ] 确认当前管理员能够在不进入 Cloudflare 后台的情况下完成日常业务成员管理。

## 3. Cloudflare 一次性授权（P7）

- [ ] 资产所有者或现有 Super Administrator 邀请受托技术运维负责人使用其自己的 Cloudflare 身份。
- [ ] 按职责授予最小权限；只有明确需要独立管理 Account Members / account-owned token 时才授予相应高权限。
- [ ] 记录正式 Worker、D1、R2、域名、WAF 和生产环境名称，不记录密码、`AUTH_CREDENTIAL_PEPPER`、`BOOTSTRAP_TOKEN` 或 API Token 明文。
- [ ] 验证受托运维负责人无需资产所有者登录即可查看运行状态、轮换 Secrets 并执行授权范围内的维护。

## 4. GitHub 与 CI/CD（P7）

- [ ] 代码仓库由受托维护人自己的 GitHub 身份访问，不共享资产所有者账号。
- [ ] Cloudflare account-owned API token 按发布实际需要配置最小权限。
- [ ] Token 存在 GitHub Secrets / Environment Secrets，不写入仓库、日志、前端或模板。
- [ ] 生产 Environment 设置明确分支和审批规则；普通 push 不默认直接发布生产。
- [ ] 实测一次资产所有者不登录 Cloudflare的受控发布、数据库迁移演练和回退。
- [ ] 轮换 CI Token 后再次发布成功；撤销旧维护人权限后 CI 和系统仍正常。

## 5. 数据与恢复（P7）

- [ ] D1 正式迁移前有可验证备份。
- [ ] R2 附件清单和实际对象一致。
- [ ] 在隔离环境完成一次 D1 恢复演练。
- [ ] 记录生产版本、迁移版本、备份位置、回退步骤和紧急联系人。

## 6. 移交完成判定

只有同时满足以下条件，才能称为“系统已完全移交日常运维”：

1. 应用管理员可独立管理业务成员和权限；
2. 技术运维负责人使用自己的 Cloudflare/GitHub 身份；
3. 发布和迁移不依赖资产所有者个人登录态或个人长期 API Token；
4. 已实测发布、迁移、回退、Token 轮换、旧维护人撤权和恢复路径；
5. 资产所有者可以只保留最高兜底能力而不参与日常操作。
